# StudyMate TDD 测试策略

## 1. 开发循环

每个需求使用以下循环：

~~~text
需求 -> 验收标准 -> 失败测试 -> 最小实现 -> 测试通过 -> 重构 -> 更新文档
~~~

## 2. 测试层级

| 层级 | 目标 | 是否调用真实模型 |
|---|---|---|
| Unit | 测试纯函数和领域规则 | 否 |
| Integration | 测试加载、检索、回答流程 | 使用 Fake LLM |
| Contract | 测试模型输入输出契约 | 默认使用 Fake LLM |
| CLI | 测试命令和交互行为 | 否 |
| Evaluation | 测试真实问题集和回答质量 | 可调用真实模型 |

## 3. Fake LLM 要求

Fake LLM 必须支持：

- 返回合法 Answer。
- 返回格式错误的响应。
- 抛出超时错误。
- 记录收到的 prompt 和上下文。

这样可以测试：

- 格式错误重试。
- API 失败处理。
- 是否把检索结果发送给模型。
- 是否泄露不该发送的内容。

## 4. 第一批测试用例

### 文档导入

- 只读取 Markdown 和 TXT。
- 忽略 PNG、EXE 等不支持类型。
- 空文件不生成 Chunk。
- 重复导入相同文件不会重复记录。
- 文件不存在时返回明确错误。

### 检索

- 相关文档排名靠前。
- Top-K 生效。
- 无结果返回空集合。
- 返回结果包含路径和行号。

### 输入识别

- 问句识别为 question。
- 学习目标识别为 goal。
- 单个概念识别为 keyword。
- /help、/sources、/reset、/quit 识别为 command。

### 回答

- 回答包含引用。
- 引用必须来自检索结果。
- 没有证据时拒答。
- confidence 不得超出 0 到 1。
- 模型格式错误时触发重试。

### 会话

- 连续追问可以使用当前上下文。
- /reset 后不再使用旧上下文。
- 会话消息按顺序保存。

## 5. 测试数据原则

- 单元测试使用临时目录和最小 Markdown 文件。
- 集成测试使用固定的 Fake LLM。
- 评估测试使用独立 JSONL 数据集。
- 不使用公司保密数据。
